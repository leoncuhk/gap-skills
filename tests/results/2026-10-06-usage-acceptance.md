# gap 0.6.1：目标审视与实际使用验收

代码基线：`0e04159`，双平台manifest均为0.6.1，验收开始时工作区干净。本轮没有增加功能、改变skill、安装全局组件或发布，只留下具体使用产物和检查结果。

## 总目标与达成程度

目标是让人与AI组成能持续把真实工作做得更好的协作系统：人负责目的、价值取舍和必须由人承担的判断；AI负责查证、实施、测试、状态接续与收尾，并把有证据的经验用于后续任务。当前已经具备可使用的协作方法和本地证据机制，总目标**部分达成**；持续减少真实工作中的纠偏、核查和接续劳动尚未测得，不能宣称总体效果达成。

| 环节 | 当前证据 | 判断与边界 |
|---|---|---|
| 理解目的 | 单一入口先区分环境事实与人的决定，保留目的、不可替换语义和判据；前次容量/展览任务保留人的实质选择 | 合成任务已有证据；不能保证任意真实任务都理解正确 |
| 查证、实施与测试 | 30项回归、包校验；三臂实际修复和独立正反例、调用探针、回退重放 | 已能完成具体本地工作，未证明比原生agent更优 |
| 独立验收 | 前轮真实独立审查找到并复验两项代码缺陷；合成产物有独立验收 | 具备且使用过；本轮只做同一agent使用演示和自审，不能冒称新增独立认证 |
| 状态接续与收尾 | 本轮真实读取旧检查点，拒绝过期通过记录，保留历史并修正到当前依据 | 该文件型案例通过；哈希只检查声明的文件，不能覆盖未声明依据或替代业务判断 |
| 用户理解、判断与控制 | 默认文字，按需证据视图；反馈不授权、不自动执行；本例保留例外政策判断 | 状态与控制边界可核查；真实用户理解、浏览器交互和省时效果仍未验收 |
| 经验保留 | 候选/已验证经验分开，记录适用范围和采用/试用/拒绝；前次增强臂实际保留拒绝不适用经验 | 已有记录与限定调用证据；本轮未额外测试经验调用，尚未证明跨任务累积收益 |
| 下一次改进 | 根据失败、正反控制及对照检验小改动，保留未通过和未知 | 方法已执行；后续应观察正常真实任务和人介入负担，继续避免功能堆叠 |

依据：[前轮独立验收](2026-10-06-batch2-independent.md)、[Matt吸收独立验收](2026-10-06-matt-adoption-independent.md)。没有胜过基线不等于现有功能无效，也不能用功能有效推导总体协作收益。

## 当前如何使用

已实际读取本机仓内 `skills/gap/SKILL.md`，并按入口的接续分支加载delivery及相应审阅说明。Mac命令执行正常。检查了本仓 `.agents/skills/gap`、`.claude/skills/gap`，以及用户 `.agents/skills/gap`、`.claude/skills/gap`、`.codex/skills/gap`，均不存在；Claude已注册插件列表没有gap。Codex插件快捷命令注册未验证。因此目前采用已实测的**显式文件路径入口**，不声称 `$gap` 或 `/gap` 已安装可用。

在目标项目的agent会话中粘贴以下提示，补充自己的目标即可；不需要先安装或手动调用helper：

```text
读取并按 /Users/leon/Documents/harness/workflow/gap-skills/skills/gap/SKILL.md 工作。
目标是：[要完成的真实工作及成功条件]。
必须保持：[已有目的、事实口径、原始材料与范围边界]。
你负责查证、实施、测试、检查实际状态后接续和收尾，沿用项目已有记录。
仅把无法从环境查明、会改变目的/价值取舍或必须由我承担的判断交给我，并说明选项与影响。
完成时给出产物、实际验证证据、剩余判断和适用于下一次任务的经验；未证明的效果明确保留。
```

本例可直接复制的使用请求：

```text
读取并按 /Users/leon/Documents/harness/workflow/gap-skills/skills/gap/SKILL.md 工作。
在该仓库内，将 examples/evidence-review/mvp 复制到一个尚不存在的新示例目录，保留原件。
接续其中已有 state.json，依据当前 policy.txt 修正过期的 draft.txt；保留原稿、历史回执和人的例外政策判断。
自行完成过期证据拒绝、修正前后检查以及简短交付，不发布、不替人决定例外政策。
```

## 本次实际结果

采用既有MVP输入，先冻结[目标和判据](../../examples/evidence-review/usage-acceptance-2026-10-06/acceptance.json)，再实际运行。没有重建检查点、降低判据或为了全绿清除人的判断。

| 实际检查 | 结果 |
|---|---|
| 接续旧状态 | 当前依据21自然日，旧稿14天；checkpoint将旧回执标为stale，退出1 |
| 直接重用旧通过记录 | 拒绝，退出2；状态未变 |
| 同一内容校验器 | 修正前退出1；修正后退出0 |
| 历史保留 | 修订1→2，原回执作为前缀保留；旧稿与原MVP哈希不变 |
| 版本绑定反馈 | 旧反馈拒绝退出2；当前合成反馈读入退出0，applied=false、authorization=false，状态未变 |
| 最终状态 | 产物就绪、运行结束；人的例外政策待决定、独立验收未建立，故总check仍为1 |

最终总check为1是该案例的预期验收结果：AI应完成已授权的事实修正，但不替人决定例外政策。所有冻结的本地**使用检查**通过，不等于虚拟业务的所有判据已完成。用户无需现在为这个合成场景作决定。

## 限制与后续

本轮证明显式路径入口、已有文件检查点接续、过期证据拒绝、依据修订、当前内容验证和判断边界在此例可用。它不证明自动发现、泛化理解、独立认证、真实用户省时或业务改善。原有HTML浏览器工具拒绝及禁止替代路线的边界仍有效，本轮没有尝试绕过；浏览器QA保留未验收。这份短案例使用文字即可，不要求用户替AI做例行验证。

下一步是在正常真实任务中继续使用现有入口，由AI承担例行核查并记录返工、用户纠偏、接续遗漏和经验采用结果；只在工具确实无法执行或判断必须由人承担时请求介入。没有新增框架的需要。
