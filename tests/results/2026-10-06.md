## 目标、版本与实际范围

目标是减少真实工作中的目标漂移、无依据完成和接续劳动，而不是增加流程或构建运行时。冻结判据与预算见 [plan](2026-10-06-plan.md)。

- 基线：`c7a2fabd2f00f1ed9b29cf809a0bf70bf4af23f1`，起始工作区干净，原有 8 项测试通过。
- 初次冻结实现：`b8ab8e7f02f974fcff33990b2521381daf20a6b8`；前向任务用此固定版本。
- 修复版：`5bd5fe68cb939c1ebd41056485a2fd434e68cb29`；独立代码复审使用此版本。
- 保留单一 `gap` 入口、原有 9 个按需参考和 7 个模板；增加一个随 skill 安装的 Python 3.10+ 标准库 helper，无新依赖、执行器或后台服务。
- 模型仅能确认**请求**为 `gpt-6-astra/high`。委派及独立 agent 均指定此配置，没有请求换模；支持接口没有暴露后端实际身份。

`checkpoint.py` 保存目的/语义/判据及修订来源，以真实文件内容和软链接目标绑定回执；输入、输出或目标变化使旧证据失效。它只报告已登记证据的连续性，不解释业务真相、不认证审查者、不执行任务或外部动作。Quick 路径仍不创建流程文件。经验记录区分候选/有限范围已验证以及 apply/trial/reject，不自动晋升。

## 开发回归与修复

四个合成历史机制位于 `tests/fixtures/collaboration`，外置 evaluator 为 `tests/evaluators/collaboration.py`，已知正确产物位于 `tests/reference-solutions/collaboration`。错误控制四项均失败，正确控制四项均通过：原件保真、消息而非事件口径、名单不等发送、接续不重复操作。它们是人为构造的开发回归，**不是**旧 gap/新 gap 的模型比较。

独立审查没有只看单元测试绿灯：

1. 独立发现：旧 helper 保存软链接解析后的路径，换源后可能仍检查旧文件而误报有效。修复保留声明路径、文件哈希与目标身份；包括等内容但换目标的回归。
2. 开发自查、独立复现：审查绑定全部历史回执，目标合法修订后被废弃产物仍可能阻塞新审查。修复为仅绑定当前修订、当前判据的最新回执。

第 1 轮修复后，两项独立复现和全部 21 项测试通过。未降低原判据；没有第二轮代码修复。

## 前向任务：有限结果与协议失败

验收者在开发冻结前另行准备两个未见变体，开发者未看题目/答案：来源口径分析，以及中断后在原产物上更新与核对发布状态。每题各运行薄约定基线和 gap 增强，新上下文、相同请求模型、相同源输入；每臂预算 12 次工具调用或 10 分钟。

| 首轮任务 | 薄约定基线 | gap 增强 |
|---|---|---|
| 来源口径分析 | 产物通过；4 调用；59.80 秒 | 产物通过；4 调用；49.82 秒 |
| 中断后原产物更新 | 产物通过；5 调用；39.89 秒 | 产物通过；5 调用；48.31 秒 |

时间是审计工具记录的首次到末次工具调用跨度，不是完整服务端计费时长；token/金额均未知。不能从这些数字计算或宣称效率改善。各任务对“queued 不等已发布”、未验证经验、缺少独立验收保持了恰当限制；HTML 的浏览器视觉表现未验证。

**保留失败：**验收者把首次 solver 提示的部分措辞转述，而不是逐字使用冻结文件；之后自行启动了 3 个纠正上下文，超过两对任务的冻结范围。开发者获知后立即禁止继续并要求中断；3 个均中断，额外观察到 3、2、0 次工具调用，未启动第 4 个。额外费用/token 未知。这不是用户介入节省的证明，也是本次开发协作的一次真实预算控制失败。首次结果只作初步行为证据，不能算严格配对验收通过。

独立原报告见 [review](2026-10-06-independent-review.md)，逐项判定见 [scores](2026-10-06-scores.json)，时间/成本缺口与预算偏差见 [metrics](2026-10-06-metrics.json)，独立固定树命令回执见 [verification](2026-10-06-independent-verification.json)。完整合成输入、真实产物、提示包装和 evaluator 保存在本地 `tests/results/2026-10-06-evidence.tar.gz`，已加入 Git 忽略以避免把模型原始产物提交公共仓；解压后 README 给出四项 outcome evaluator 的重跑命令。导出内 SHA256 清单已核验；不含原始推理或会话转录。

## 最短使用与复验

直接让当前 agent 读取仓内 `skills/gap/SKILL.md` 并按任务执行；无需全局安装。已安装时：

```text
$gap 从实际产物和最新证据继续这个任务；保留原目标与口径，只重查失效的部分，完成后区分产物、独立验收和待判断事项。
```

需要跨会话证据时，按 [delivery procedure](../../skills/gap/references/delivery.md) 使用 helper。当前研发自身的可检查停点为 [state.json](2026-10-06-state.json)，对应 [contract](2026-10-06-contract.json)。它应明确保留配对协议失败，不能因工程通过而全绿。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/validate.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
python3 skills/gap/scripts/checkpoint.py --root . --state tests/results/2026-10-06-state.json check
```

最后一条预期 exit 1：配对协议未满足，这是正确的剩余状态。helper 的 `--help` 提供 `init/record/check/revise/end/use` 六个命令。
