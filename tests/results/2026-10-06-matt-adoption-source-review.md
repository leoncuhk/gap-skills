# Independent review of frozen Matt-adoption variants

Scope: exact frozen old/full/pruned skill snapshots supplied by the coordinator, baseline `cea4bd41a4434f6795d334b7796998695ef1ab1f`. This review precedes solver outcomes. No gap code or skill file was edited by the reviewer.

## Findings

No blocking source defect found in the two proposed reference changes. The retrospective addition correctly distinguishes absent checks from checks that exist but are disconnected, skipped or have their failure swallowed. Its bad/valid controls exercise the caller rather than merely checking a helper in isolation, and it expressly limits local evidence relative to remote CI and branch protection. The communication addition asks for comparable executed evidence and concrete rollback effects, with explicit exceptions for small edits. It does not require a template, diagram, new tool or process for every change.

The authorization boundary remains coherent: the operating contract requires scope or approval for environment changes, while the retrospective's existing closing instruction explicitly permits changes already authorized by the current request. The synthetic task gives that authorization in advance. The new language does not authorize automatic self-modification or production operations.

The deletion experiment is appropriately narrow. Full and pruned differ by one sentence about whether HTML is worth its cost; the surrounding guidance still selects the lightest useful medium and explicitly forbids turning a short answer into a web page. Passing this one task would support only provisional deletion for the tested scope. Old versus full changes several mechanisms together and cannot identify the causal contribution of an individual addition. A single run per arm cannot establish reliable equivalence, generalization, statistical improvement or efficiency.

The longest addition concentrates comparison design in one paragraph. It is dense, but remains confined to the suspected-no-op branch and adds no mandatory work for unrelated tasks. There is no evidence yet that its added instruction cost is repaid; that remains an empirical limitation, not a source-level defect.

## Protocol limits to retain in the final report

- All arms are explicitly directed to retrospective and communication. This establishes controlled exposure and does not validate automatic branch selection or on-demand discovery.
- Both requests share one context. The small note change is not a fresh-context Quick test.
- The task itself expressly requests before/after evidence, rollback impact and a bounded claim, so successful behavior cannot be attributed solely to new skill prose.
- The fixture is small and intentionally solvable; success proves only this local gate repair under these conditions.
- The skill files are installed as immutable inputs and are checked against frozen per-arm hashes.
- Raw project and sample hashes, a known-failing baseline, a known-green reference repair, six private controls and a causal checker-invocation probe are retained. Objective outcomes are judged by execution and hashes, not narrative keywords.
- Complete platform call counts, token usage, actual backend and full run timing stay unknown unless independently evidenced. Submitted receipt files alone do not prove an actual before/after run; trace completeness is separately reported.

A final source review should also inspect the coordinator's eventual adoption diff and reports after outcome-based selection. This review does not certify package metadata or claim that the experiment has passed.
