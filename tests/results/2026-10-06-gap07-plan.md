# gap 0.7: human-readable delivery and scoped experience

Baseline: `022a4a6` (0.6.1). User authorizes implementation, safe local tests, independent review and bounded iteration in gap only. No global install, external services, production, publishing, neighboring-repo edits or browser restriction bypass.

## Outcomes frozen before solver execution

1. A reader can identify actual changes, their impact, supporting original text, outstanding human choice, options and consequences. Text and HTML derive from the same data. Technical hashes alone do not satisfy this outcome.
2. Citation identity and bounded source excerpts are verifiable; changed cited source makes the explanation stale, including when checkpoint state did not change. Feedback cannot approve, mutate criteria or silently become an external action.
3. An experience records its originating failure, applicability/exclusions and correction. Validated application needs current evidence from distinct validation tasks and a current-task scope basis. Actual use needs an observed result or remains unverified. Reading or saving an entry does not prove improvement.
4. Existing plain checkpoint/Quick usage remains available without forcing a brief or structured experience onto every task.
5. A development pair and a withheld transfer pair use identical raw task information, task prompt and requested configuration within each pair. Independent evaluation checks meaning/information completeness against raw sources; it is not a human-understanding experiment.

## Minimal implementation and ownership

Use the html-workbench source-location, export/read-back and provenance principles, not its full runtime or directory layout. No video or generic graph generator. Add a small packaged experience validator used by existing `use` and a result-recording command; no scheduler or global learning loop.

Main owns checkpoint integration and brief/view code. A developer owns experience validation and its tests. Independent acceptance owns frozen synthetic cases, negative/positive controls, source review and result grading. All requested agent configurations are gpt-6-astra/high; actual backend identity is not attested.

## Budget and evidence

Initial budget: four solver contexts total (development baseline/enhanced, transfer baseline/enhanced), each at most 18 tool invocations / 12 minutes, no solver delegation. Baseline gets the same sources and task requirements with a thin contract; enhanced gets installed gap. Main alone dispatches exact generated envelopes. Independent review and developer work use separate contexts. Repair identified implementation defects and rerun affected deterministic tests; do not rerun solver arms merely to obtain wins. Any new solver budget needs an explicit recorded reason before launch.

Frozen acceptance is not weakened after observation. Preserve failures, source changes, self-report versus observed evidence, genuine human intervention needs and unknown time/cost. Full platform traces may be unavailable; independently replayable outcomes remain useful but cannot authenticate every historic action.

Real browser QA is blocked by the prior explicit tool denial. Do not use another route to bypass it. Source, unit/CLI and simulated-DOM checks proceed and remain separately labeled. Real human understanding and sustained real-work benefit require later actual use; this batch cannot certify the whole long-term goal.
